## Scope and evidence boundary

The review inspected the public source for the extension wiring, controller configuration, state construction, selection, Jev adapter, persistence, lifecycle, replay, paired-pilot entrypoint, selected tests, CI, and installation documentation. The supplied original AGENT_HANDOFF.md was also consulted. Source citations below resolve to the reviewed immutable revision.

Git checkout failed in the review environment because GitHub DNS resolution was unavailable to the container. Public raw source was readable through web tools. The reviewer did NOT install the repository, run its full test suite, execute a live Pi trajectory, make a paid TypeSafe call, or run comparative benchmarks. Existing checked-in test reports are not independent verification by this review.

The failure sequences below are control-flow deductions from the inspected source, not claims that an automated reproducer was executed. Add executable regression tests before changing the behavior. This is a focused reliability/evaluation review, not an exhaustive security audit or proof that no other defects exist.

## Recommendation

Keep the architecture. The separation between LLM proposals, a controller-owned Jev selection, and the existing experiment runner is appropriate. Do not rewrite the project or add another reasoning strategy yet.

Do not release this revision as restart-safe unattended Jev autoresearch, and do not treat its pilot reports as evidence of Jev-versus-LLM performance. Fix runtime invariants first; then demonstrate one live end-to-end trajectory; then implement and execute the actual comparison.

## R1. Persist actual run results; never infer completion from a working tree

### Source trace

`ControllerLifecycle.recordBenchmark()` stores a `benchmark_completed` event containing a decision ID and patch hash. It does not persist the actual benchmark result or correctness verdict. The keep rejection in `log_experiment` depends on `runtime.lastRunChecks`. `reconstructState()` resets that value to null. [S1, S2]

`prepareControllerLog()` also allows a pending `running` decision to acquire a benchmark-completed association by hashing the current tree. A tree hash proves identity, not that a process finished or tests passed. [S3]

### Regression sequences

A. Establish a baseline, select an experiment, make its edit, run a benchmark whose correctness checks fail, restart/reload the extension, then attempt `log_experiment` with status `keep`. The persisted state must reject this independently of what the LLM remembers.

B. Start a selected run, terminate the process before it completes, restart, and attempt to log a successful metric. A recovered `running` record without a completed result must not become a successful measurement merely because its files exist.

### Required fix

Add an immutable, runner-owned run receipt. Persist it before exposing a completed benchmark to the agent. Include a unique run ID, optional decision ID for baseline runs, segment/epoch, input source identity, command/workload/checks identity, start/end times, exit code, timeout/abort state, authoritative metrics, and correctness status.

A conceptual schema, to adapt to existing contracts rather than copy blindly:

```ts
interface RunReceiptV1 {
  version: 1;
  runId: string;
  decisionId: string | null; // Explicit baseline exemption only.
  segment: number;
  epoch: number;
  parentCommit: string;
  targetSnapshotHash: string;
  benchmarkHash: string;
  checksHash: string | null;
  command: string;
  startedAt: string;
  finishedAt: string;
  exitCode: number | null;
  termination: "completed" | "timeout" | "aborted" | "process-error";
  metrics: Record<string, number>;
  checks: {
    required: boolean;
    status: "pass" | "fail" | "not-run" | "error";
    outputHash: string | null;
  };
}
```

Do not substitute a generic numeric metric parser for an explicitly defined benchmark protocol. Define how the target benchmark supplies machine-readable metrics, validate finite values and the configured objective, and preserve raw output for diagnosis. A receipt may record an unsuccessful run; that does not make it eligible to keep.

`log_experiment` should reference the receipt. Agent-supplied metric/check values must either be ignored in favor of authoritative fields or rejected on mismatch. Missing required checks are not a pass. Without a valid receipt, recovery should mark the run interrupted/unknown and require rerunning or an explicit unsuccessful disposition.

Migration: old hash-only events do not prove correctness. Preserve them as history, but require remeasurement before retaining an unresolved pre-migration run. Do not promote old null checks to passing checks.

## R2. Bind the measured artifact to the retained artifact

### Source trace

The write/edit preflight checks pending selection and file scope but does not freeze edits after measurement. In the normal `awaiting_log` path, `prepareControllerLog()` uses the recorded benchmark patch hash without verifying the current target tree. The keep path stages the current working tree. [S1, S3]

### Regression sequence

Select candidate X -> edit approved file to patch A -> benchmark A -> edit that same approved file to patch B -> log keep using A's result. This must fail rather than associate A's metric with retained B.

### Required fix

Freeze the target snapshot before running, verify it after the benchmark/checks, and verify it immediately before finalization. Prefer measuring an immutable snapshot or dedicated worktree. Ordinary mutation tools should reject target writes while a run is executing or awaiting finalization. If a target changes, mark the receipt stale and require a new measurement.

Protect the same definition of target identity throughout: tracked/untracked target files, deletions, renames, modes, symlinks, and the intended parent revision. Explicitly exclude controller append-only records and documented generated benchmark artifacts; do not let exclusions hide source or evaluator modifications.

A scope guard is not a sandbox. Shell tools or another process can modify files, so the identity check must remain even when write/edit hooks are correct. Use isolated worktrees and external evaluator protection in comparative runs.

## R3. Make keep/discard finalization recoverable and success-aware

### Source trace

`log_experiment` can turn Git or JSONL write failures into warnings and proceed to `completeControllerLog()`. The revert subprocess result is not checked for a nonzero exit code. Runtime results are updated before finalization is known to be successful. [S1]

### Regression sequences

Inject an `EACCES` or disk-full failure when appending the experiment log; separately simulate nonzero `git commit` and nonzero revert exit codes. The controller must not consume the decision, announce successful retention/reversion, and start a fresh selection with an inconsistent history/tree.

### Required fix

Use a durable finalization intent with a unique run ID and explicit stages. Verify the Git operation, persist/deduplicate the experiment outcome, then mark controller completion. A crash between stages must reconcile those stages idempotently, not repeat commits or append duplicate experiment rows.

An upstream log link alone is insufficient proof of completed finalization if it could have been written before a failed revert. Store enough information to verify the retained/reverted tree. Surface I/O failures as a paused, recoverable operation, not a successful result with a warning.

Do not pretend Git plus multiple files form one atomic transaction. Implement a small write-ahead protocol and reconciliation. Keep the disabled-controller behavior unchanged unless making an explicitly separate upstream-compatible bug fix. Apply equivalent validated finalization rules across evaluation arms.

## R4. Treat broken configuration as an error, not as controller off

### Source trace

`loadControllerResolution()` maps unparseable/unreadable configuration to off. `isJevControllerActive()` catches invalid enabled-config errors and returns false. Enforcement in the extension relies on that boolean. A prompt warning does not substitute for refusing the operation. [S1, S3, S4]

### Regression sequence

Start a Jev-enabled session with a baseline and no pending selection. Change `candidateCount` to an invalid value, or corrupt the JSON. Request a target edit or post-baseline run. The operation must remain blocked rather than use the controller-off branch.

### Required fix

Represent three states explicitly: off, enabled, and configuration error. A missing controller section at initial startup or an explicit valid off mode may preserve upstream behavior. Malformed or inaccessible configuration is not evidence of operator intent to turn the controller off.

Once a session is enabled, unexpected deletion or corruption must not downgrade it. Persist/freeze the active controller identity or require an explicit operator-controlled mode change. Every mutation/run/log/autoresume entrypoint should use the same resolver and fail closed on errors. Safe read-only inspection and operator repair should remain possible.

Test absent/off parity separately from malformed-input handling; do not redefine configuration corruption as valid off mode simply to preserve a convenient parity test.

## R5. Make pause/resume durable and usable

### Source trace

`resumeController()` changes state in memory and can append `pending_invalidated`, but it does not append an event that durably clears the pause. Journal folding ignores `pending_invalidated`; recovery can rediscover the earlier global pause. Selection invokes recovery. The inspected command wiring does not expose a controller resume action. [S1, S2, S3, S5]

### Regression sequences

Pause after a provider failure -> fix the provider configuration -> invoke resume -> reconstruct the lifecycle -> select again. It must remain resumed. Also pause with a pending decision, invalidate it, remove/recreate the pending snapshot, and recover: that invalidated decision must never reappear as runnable.

### Required fix

Add an explicit operator command, such as `/autoresearch controller resume`, with documented behavior. Persist a `controller_resumed` event and handle it in ordered journal reduction. Treat decision invalidation as terminal for that pending association.

Resume should not silently erase measured-but-unfinalized work. Define whether an existing receipt must first be finalized or deliberately abandoned. Stop automatic continuation while the controller is paused. Do not give the research LLM an unrestricted ability to clear cancellation caps or repeatedly unpause provider failures.

Preserve history and budgets through resume. Recovery should be a deterministic reduction of events, not a combination of loosely independent overlays whose state can disagree.

## R6. Scope Jev's factual state to the active objective/segment

### Source trace

`snapshotFromRuntime()` forwards all runtime results and drops their segment identity. The downstream builder chooses baseline/best values and budget counts from those forwarded runs. The controller wiring still uses a fixed epoch constant. [S1, S3, S6]

### Regression sequence

Segment 0 has a time baseline 100 and retained result 80. Segment 1 changes the objective to size and establishes baseline 1000. Inspect the actual Jev request. Its active baseline/best must be 1000, not 100/80, and its segment budget must not count segment-0 attempts.

### Required fix

Filter to the active segment/objective before aggregating. Preserve original global run IDs when filtering; otherwise `run-N` evidence references can point to a different experiment. Retain explicit segment/epoch/metric identity in projected records.

Separate active-segment attempt counts from trial-global limits. Starting a new segment may reset the segment baseline, but must not reset total trial dollars, elapsed time, or allowed experiments.

Wire epoch changes through objective/policy transitions and recovery. For V1, an acceptable simpler alternative is to reject objective/segment changes while a Jev-controlled experiment session is active and require an explicit fresh session. Do not silently continue with mixed metrics or an old frozen policy.

## R7. Do not expose mock analysis as a live pilot

### Source trace

`runPairedPilot()` gates live mode on an API key, then injects deterministic first-/last-eligible mock selectors and demonstrates revalidation with mock artifacts. The latest revision explicitly says trajectories are planned, not executed, which is a useful correction. However, top-level transport/status fields can still identify the report as live, and the actual trajectory executor is absent from this path. [S7]

### Regression sequence

Set a nonempty test key and invoke the documented live entrypoint with networking instrumented. No completed live comparison should be reported unless real selector calls and actual experiment trajectories occurred. An API key's presence is not proof of any execution.

### Required fix

Split planning, fixture replay, and live execution into distinct commands/modes. Until the real executor exists, a requested live execution must report not implemented/blocked and exit nonzero. Planning may succeed, but its report must remain explicitly a plan.

Suggested report fields:

```json
{
  "requestedMode": "live",
  "executedMode": "none",
  "status": "not_implemented",
  "providerCalls": {"pi": 0, "jev": 0},
  "completedTrajectories": 0,
  "outcomeSource": "none"
}
```

Keep fixture results in a separately labeled diagnostic section. Do not describe measured failures, unknown prices, or absent measurements as zeros. Update milestone completion claims to distinguish plan validation from actual trajectory execution.

For the real executor, run a pinned upstream arm A, a structured-LLM arm B, and a Jev-selection arm C. Use the same initial task revision, model/environment policy, generator protocol for B/C, frozen question plan, workload seeds, protected evaluator, and declared budget. Each trial needs a fresh conversation, isolated target worktree and caches, real artifacts, complete cost accounting, and independent revalidation. A manifest describing isolation is not itself isolation.

Use an actual pinned upstream checkout for A unless differential tests genuinely establish equivalence to it. Absent-controller versus explicitly-off tests within the same fork do not by themselves establish parity with unmodified upstream.

First run one short live smoke trajectory; only then spend on a small A/B/C pilot. No eval platform is required to fix these fundamentals.

## R8. Replay the full decision envelope, not only option descriptions

### Source trace

`FrozenReplaySnapshot` contains a decision state, but `ReplaySelectorInput` and the input object passed to the selector omit that state. The replay adapter receives an instruction, option descriptions, IDs, and hashes, without the underlying measured history/evidence/budget. [S8]

### Regression sequence

Create two snapshots with identical option wording but different observed bottleneck evidence. Have the selector test double assert it receives that evidence. The existing input contract cannot satisfy this through its declared fields.

### Required fix

Introduce a canonical selection envelope shared by runtime and replay. It should contain the complete sanitized state, compiled instructions, presented option ordering, schema version, policy identity, and semantic input hash. Provider-specific wrappers may differ, but the relevant evidence and candidate information must match.

Keep future outcomes in a separate data structure not reachable from the selector. Add one sentinel in observed evidence and another sentinel in hidden future labels; the former must be present in the request and the latter absent. Compare the normalized envelope hash captured during runtime with the replay hash.

Also make correctness part of outcome eligibility in replay grading. A positive numerical result with failed or missing required checks must not count as a successful optimization. Failed implementations are outcomes/costs, not observations to silently drop from the primary success comparison. Keep raw measurement missingness explicit and predeclare how invalid attempts affect trajectory utility and failure rates.

## R9. Repair the CI tracked-output predicate

The workflow ends by asserting that `git ls-files site/build docs` is empty, but `docs/upstream-baseline.json` is tracked at the reviewed revision. That predicate cannot pass when the job reaches it. The workflow also excludes pushes to main. [S9, S10]

Restrict the check to actual generated outputs, or move source documents into a clearly non-generated directory. Enable checks on the relevant main pushes, and retain pull-request checks. Run the complete workflow, including the site build, rather than only the unit-test command.

## R10. Make the installation path identify this fork

The README quick start points to `npm:pi-autoresearch`, and package metadata still identifies upstream. A user following the guide is not directed to the Jev fork. [S11, S12]

Document a verified, revision-pinned fork installation or local extension load, its dependency installation, TYPESAFE_API_KEY setup, Jev opt-in, and a five-experiment smoke session. If publishing separately, use a distinct package name and correct repository/homepage/issue metadata. Preserve upstream copyright and license attribution.

Warn against loading upstream and the fork simultaneously because they share extension commands/tools. Include pause/resume instructions after R5 lands, and an explicit statement that synthetic eval reports are not live comparisons.

## Implementation order and pull-request boundaries

### PR 0: Restore an honest development baseline

Fix CI and quick-start pointers (R9/R10). Record the new fork SHA, runtime/package-manager versions, installed dependency versions, and actual test output. Do not overwrite historical baseline data with a claim that was never rerun. Keep a clean pinned upstream checkout for differential checks.

### PR 1: Controller activation and recovery

Address R4/R5. Introduce explicit error states, durable resume/invalidation, paused auto-loop behavior, and operator-only recovery. Tests must exercise the registered extension entrypoints and reload, not only isolated reducers.

### PR 2: Measured artifact and result finalization

Address R1/R2/R3 together. Add authoritative receipts, snapshot identity validation, recoverable finalization, and I/O fault injection. Keep the external runner architecture; do not build a replacement research platform. Explicitly migrate old unresolved records by requiring remeasurement.

### PR 3: Correct state boundaries

Address R6. Preserve evidence IDs, isolate objective/segment aggregates, and maintain independent trial-global budgets. Either implement epoch rotation or explicitly constrain V1 to one objective per controller session.

### PR 4: One canonical runtime/replay envelope

Address R8. Prove actual request equivalence, outcome-label separation, and failure-aware grading with cheap tests.

### PR 5: Actual live comparison

Address R7. Make unimplemented live mode fail honestly immediately, then add a real trajectory executor. Do not mark execution complete on the basis of manifests or mocked callbacks. Run one live smoke session, then a small predeclared pilot, and report uncertainty and failures.

These PRs should not add expectimax, adaptive question rewriting, composite scoring, model training, or a new dashboard. Such changes would complicate attribution before the existing design is trustworthy.

## Regression-test matrix

Use temporary Git repositories and dependency-injected runner/provider/storage adapters. Test full registered-tool flows in addition to pure functions. Start with failing tests against the reviewed revision. Test names below are proposed, not claims about existing tests.

| Test | Scenario | Required invariant |
| --- | --- | --- |
| config-absent-off-parity | No controller / explicitly off | Upstream behavior and no key required |
| config-invalid-enabled | Invalid Jev field or malformed JSON | Target edit/run cannot bypass selection |
| config-removed-mid-session | Enabled config disappears | Session pauses; no implicit downgrade |
| checks-failure-survives-restart | Failed checks, fresh runtime, log keep | Keep rejected from durable evidence |
| interrupted-run-no-receipt | Crash after run_started | No successful log inferred from tree |
| receipt-metric-authority | Agent changes reported metric | Reject mismatch or use runner value |
| post-measure-edit | Patch A measured, patch B current | No keep until B is remeasured |
| source-changed-during-run | Target changes while measuring | Receipt invalid for retention |
| finalization-log-io-error | Experiment log append fails | Pending operation retained; no false completion |
| finalization-git-error | Commit/revert returns nonzero | Pause and preserve recoverable state |
| finalization-idempotency | Crash between each stage, retry twice | Exactly one linked experiment outcome |
| pause-resume-restart | Provider pause, operator resume, reload | Resume persists; next valid selection works |
| invalidated-pending-recovery | Resume invalidates stale pending | No resurrection from older journal entries |
| paused-autoloop | Idle agent while controller paused | No automatic repeated attempt loop |
| cross-segment-state | Different units/objectives in two segments | Baseline/best/counts scoped correctly |
| evidence-ids-after-filter | Filter segment but retain global IDs | Evidence references retain their meaning |
| trial-budget-survives-segment | Change segment within trial | Dollars/time/attempt cap not reset |
| replay-full-envelope | Same recorded runtime input replayed | Same normalized input hash and evidence |
| replay-hidden-outcomes | Distinct visible/hidden sentinels | Future labels absent from selector request |
| replay-invalid-correctness | Fast result with failed checks | Not scored as successful improvement |
| live-mode-no-stub | Request live with dummy key | Not-implemented/auth failure, never mock-as-live |
| live-smoke | One real selected implementation and measurement | Provider receipts + artifact + independent check |
| ci-generated-paths | Source docs tracked, build output untracked | CI predicate allows authored docs |

## Definition of done

For reliable V1: runtime P1 findings R1-R6 resolved with regression tests, full CI actually run, usable fork installation documented, and a live smoke trajectory demonstrating selection -> implementation -> measurement -> correctness -> log -> retain/revert. Restart at least once during the smoke and verify durable state.

For comparative evaluation: R7/R8 resolved, real A/B/C trajectory artifacts and usage recorded, evaluator protections verified, failures retained in reporting, and final artifacts revalidated independently. Report the observed result even if Jev is slower, worse, or indistinguishable. No ranking claim is a prerequisite for implementation success.

## Coding-agent task

Implement the above in small PRs. First reproduce R1-R6 with failing integration tests. Do not dismiss a defect because a leaf-module unit test passes. Preserve disabled-mode behavior; distinguish narrow upstream fixes when necessary. Remove misleading live execution statuses now, but postpone spending on comparative runs until runtime invariants hold. Return the new SHA, precise changed files, tests executed and outputs, remaining limitations, and links to actual smoke/evaluation artifacts. Never label fixture-only work as a successful live run.
